Project conventions

  • Authoritative notebooks: src/notebooks/. src/raw-notebooks/ mirrors are for read-only navigation; agents never edit/overwrite/regenerate/delete/synchronize them. Report source/mirror mismatches.
  • Public notebooks import from config.example import CONFIG; only user-managed private copies select production, in a separate kernel. Data paths use CONFIG.data_dir; artifacts use CONFIG.output_dir. Create output subdirectories explicitly.
  • Example roots are data/data-example/ and outputs/exports/; private roots are data/data-prd/ and outputs/.exports/. Directory names and ignored status do not prove synthetic provenance. Production boundaries: mem:core.
  • Prepared CSV: UTF-8, semicolons, YYYY-MM-DD dates, decimal-point monetary values without thousands separators, empty fields for missing values. Preserve source precision and leading-zero identifiers/codes as strings; preserve actual raw formats rather than silently rewriting extracts.
  • Original ERP fields retain names; descriptions use _TEXT. Current derived names: CUSTOMER_ID, PERIODSTART, ORDERCOUNT, TOTALORDERNETVALUE, AVGORDERNETVALUE, TRANSACTIONCURRENCY. Older notebook names are legacy, not the target contract.
  • Tabular workflow: load Parquet; export new/updated datasets to CSV, convert to Parquet, retain both, verify schema/values/missingness. General DuckDB CSV inference can change identifier types; successful conversion alone does not establish the contract.
  • Validate repeated order headers before retaining one row per SALESORDER; never sum repeated header amounts. Verify lookup-key uniqueness, left-join enrichments and unchanged counts/amounts. Do not join missing keys together or silently drop missing industry.
  • Separate technical representation, analytical eligibility and assessability. Follow plan eligibility policy: verify OR/observed codes; fully rejected C excluded from primary measures; partially rejected B unresolved until header amount meaning is clarified; incomplete processing alone does not exclude. Use a common eligible population for counts/totals/averages.
  • An eligible missing amount remains counted but makes its total/average unavailable; propagate missing required totals into broader monetary aggregates. Covered zero-order periods have zero count/total and undefined average; uncertain coverage is not zero activity. Recompute aggregate averages from totals/counts; monetary groups remain currency-specific.
  • Utilities follow argparse/pathlib, main() -> int, SystemExit(main()); preserve temporary-write/replace behavior. Dataset randomization utility is intentionally parameterized by explicit input/output directories.
  • Dataset randomization input prerequisite: prepare all four CSVs with the documented filenames/column sets, consistent order headers and formats matching --delimiter/--decimal-mark before conversion. The CLI description and --input-dir help state this contract.
  • setup/create_example_dataset.py maps all observed IDs across the union of related tables. Prefixes: SO orders, CU customers/SOLDTOPARTY, R reasons, I industries; append unique random 12-digit numeric suffixes. Sample without replacement, exclude original matching IDs, preserve missing keys, retain unused/orphan references and never export mappings.
  • Dataset randomization utility maps each distinct numeric TOTALNETAMOUNT consistently to a unique signed cent value; equivalent spellings share a mapping, zero/sign/missingness remain. Amount replacements are independent of original magnitudes, do not preserve monetary trends/rankings, and are not synthetic research evidence about actual spending.
  • Dataset randomization utility requires exactly the four documented column sets, checks repeated headers, rejects source symlinks/overlapping paths/nonempty destinations, hashes both read passes and stages all four UTF-8 semicolon outputs before directory replacement. Dates/statuses/currencies/item numbers/descriptions stay unchanged; full anonymisation is not promised.
  • Markdown uses centered title wrappers and manual GitHub-anchor TOCs. DocumentationPreprocessor runs after fenced-code stashing and before raw HTML: enables Markdown in centred wrappers and inserts list separators for bullets AND numbered items after bold-only labels and quoted introductions. Preserve explicit markdown attributes/code/source text.
  • Docsite styling belongs in SITE_CSS, not generated HTML/CSS. set_link_targets resolves against generated site paths: index/document/heading links use _self; other links use _blank plus noopener/noreferrer. Preserve grouped root-first index and overview navigation. Link rewriting/traversal limits: mem:suggested_commands.
  • Phase notebook template sections: purpose/context; inputs/prerequisites; configuration; execution; validation; findings/decisions; exports/report; completion/handoff. Record evidence role, run/spec versions and restrictions. Current Phase 1 requires alignment before its legacy details become guidance.
  • .githooks/pre-commit checks indexed private paths, not embedded notebook content. Keep production outputs in private copies. Durable memory graph policy: mem:memory_maintenance.
  • Utility integration tests copy file-rooted scripts into TemporaryDirectory fixture trees before executing them; never run the docsite generator against the real checkout. All test records, including temporary profile directories named data-prd, are invented. Dependency export tests use in-memory notebooks with code that must not execute.
