Safe verification and closeout

  • Follow repository defaults subject to explicit user/session overrides. Preserve unrelated changes and staged state; do not commit/push unless requested. Use existing .venv/bin/python -B; verify that execution is data-free or uses explicitly invented fixtures, never production or transformed real records.
  • Syntax: ast.parse/compile source text for changed setup/.py or src/config/.py without writing bytecode. Bash: bash -n setup/initial_setup.sh. Finish authored changes with git diff --check.
  • Data-free utility checks: .venv/bin/python -B setup/NAME.py --help for csv_to_parquet, create_example_dataset, notebook_to_raw_python, create_documentation_site. Lock consistency when relevant: uv --no-cache lock --check --offline. No incidental installation/bootstrap/LFS retrieval/Git-hook reconfiguration.
  • Dataset randomization utility tests: .venv/bin/python -B -m unittest discover -s setup/tests. setup/tests/test_create_example_dataset.py uses temporary, fully invented CSVs; covers row/source preservation, prefixed cross-table ID mappings, amount equality/uniqueness/sign/missingness, schemas, CSV locales, output/overlap protection, source mutations, decimal extremes and safe failure diagnostics.
  • No configured project-wide lint/type-check/analysis suite. The focused setup tests and notebook's embedded synthetic checks do not prove empirical phase completion or a working six-phase pipeline. Report only checks actually run; do not broaden into notebook execution without a task-specific reason.
  • Converter tests use isolated copies with entirely invented raw/interim/processed fixtures, even if a temporary fixture directory is named data-prd. Check routing, non-recursion, skip/update, input preservation and Parquet schema/value/null round-trips.
  • Docsite tests use isolated copies; real-checkout traversal hazard and anchor limitations are in mem:suggested_commands. Check lists (ordered/unordered, quoted/unquoted), preserved code/wrappers, link rewriting, internal/external targets, index grouping and styling as relevant. Generated HTML is not authoritative source evidence.
  • For notebook edits: only src/notebooks/ sources, never raw mirrors. Parse code cells and validate notebook schema; preserve no-production public outputs. Existing Phase 1 has library-tagged cells and implementation_sha256 metadata; inspect their meaning before using an isolated verification harness/updating code fingerprints. Its input/schema scope remains legacy; mem:core.
  • Do not run Run All, regenerate datasets, or inspect protected outputs during onboarding/memory maintenance. Memory refresh alone requires no analytical execution or setup.
  • Default closeout is HANDOVER.md entry → BACKLOG.md update → relevant Serena memory operations, overridden by explicit session instructions. Store durable technical facts in memories, session history/status in their own files; do not turn one session's override into a permanent policy.
  • After memory writes run serena memories check and inspect its report for dangling references; confirm only intended memory files changed. Verify active project on the exact MCP connection before writes. Memory graph/reference conventions: mem:memory_maintenance.
