Project source map and invariants

  • Bachelor's thesis: retrospective detection, typing and explanation of B2B wholesale purchasing changes from ERP time series; research repository, not a deployed application.
  • Source of truth: docs/project/bachelor_thesis_project_plan.md (English) defines objectives, scope, candidate measures and evaluation commitments. docs/framework/fuucce_framework.md operationalises it; completed data-free schema: docs/project/data_description.md (four main tables plus four mappings); evidence: docs/literature/ and docs/prompts/.
  • FUUCCE workflow: Familiarise and assess → Use data and prepare profiles → Uncover and characterise changes → Construct taxonomy → Classify and explain → Evaluate and discuss. Plan: 24-month window, time-window profile comparison, researcher-led taxonomy and rule-based assignment; prioritise order activity/value and assortment, with discounts optional and profitability excluded. Keep development and final evaluation separate; controlled and held-out cases support distinct claims.
  • AGENTS.md contains repository instructions and verified development guidance. BACKLOG.md is the ordered six-phase task tracker: stable P1.01-style core IDs, P1.O1-style optional IDs and explicit completion checks. Read task status there; do not infer completion from memories or existing documentation.
  • Executable utilities live in setup/, not scripts/. Public source notebooks belong in src/notebooks/; inspect their current contents before assuming implementation exists. Phase 1 has an assessment implementation; this is not a complete six-phase pipeline. Check source notebooks and BACKLOG.md rather than older placeholder descriptions in README/AGENTS architecture prose.
  • Phase 1 source: src/notebooks/001_f_phase_1.ipynb implements structural assessment, evidence-use boundaries, provisional profiles/exploration, decision registers and embedded synthetic verification. Implementation availability does not establish empirical phase completion; use BACKLOG.md for status.
  • Two-PC workflow: develop public source notebooks on synthetic inputs; user copies to ignored src/.notebooks/ on the production PC and explicitly selects the production configuration. Config changes roots only: declared filenames/schemas and parsing formats must also match the private extracts. Both src/config profiles are tracked generic paths, not datasets.
  • Never inspect, search, execute against or modify data/data-prd/, src/.notebooks/, outputs/.exports/, or production-derived content elsewhere. Directory names do not establish that example data is synthetic; pseudonymized records are not synthetic.
  • Markdown sources are authoritative; docs/docsite/ contains generated HTML, including copies of memories/session documents that can be stale.
  • Environment, notebook import setup and Serena connection details: mem:tech_stack. Bootstrap, utilities and path/traversal traps: mem:suggested_commands. Config/notebook/data/style rules: mem:conventions. Safe verification and closeout: mem:task_completion. Memory graph and maintenance policy: mem:memory_maintenance.
